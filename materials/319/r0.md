## 2. 交付面设计（本卡产出=研究文档，零产品代码）

**矩阵 shape（照 intel 三列）**：每轴三列 `官方文档（dated 快照）| 我方实测（可复现原始输出）| 未验证（明示缺口）`。
**行**：①附件发送 Base64 ②附件发送 URL ③消息下载 ④线程下载 ⑤内联尺寸上限 ⑥URL 尺寸上限 ⑦URL 可达性要求（无自定义 header/cookie、允重定向/预签名）⑧webhook 附件表示（元数据 vs 内容）。

**受控实测（我方侧，本机可执行、可复现）**：
1. `POST /v1/messages` 携 `attachments[]`（Base64 与 URL 两形态各一）→ 预期 **400**（strict schema），留原始响应体。
2. 无附件基线发送 → 201，证 schema 拒绝非因整路由问题（**关键对照**，防「全 400」误读）。
3. 尺寸探针：text/html 逼近 1e6 字符上限 + 请求体逼近 16 MiB → 分界实测（记录 413/400 边界与错误码）。
4. webhook：发含附件的入站信（本地 sink）→ 断言 payload 仅 `hasAttachments:true` 且无内容字段（附原始 payload）。
5. MCP：`mail_send` 同验（工具面与 REST 同 schema，证无独立附件入口）。
   ※ 方法可选：本机起 API 实例（`bun` 直跑）或测试驱动（`bun test`）；均须落**原始输出**（stdout 粘贴+脚本路径），照 #3871 附加条件 b2。

**对方侧**：仅「官方文档」列（附 **dated 快照**：抓取 https://docs.agentmail.to/attachments 正文+抓取时间），其余标**未验证**；我方不申请对方账号、不复现其生产行为。
