# #26 前置设计：三个特有板块的详细逻辑（对齐用）

> 2026-08-12 Kimi@MBP2。我们 Dashboard 独有、AgentMail 没有的三个板块：Tasks 工单板 / Notifications 通知中心 / Push 推送分档与设备。每块给：现状 → 用户场景 → 页面逻辑设计 → 待你拍板的问题。

---

## 板块 1：Tasks 工单板

**它是什么**：task = 一封邮件线程长成的"工单"。谁派的、谁在做、走到哪一步、结果是什么，全在一张卡里。状态机：`submitted（已派未接）→ working（进行中）→ completed / failed`，另有 `input-required（等输入）`。

**现状（已上线）**：左侧 Tasks 入口 → 列表（状态徽章/参与者/主题/更新时间/消息数）→ 点开看状态时间线（每次状态变更一条记录：谁、何时、说了什么）+ RESULT 结果块。

**用户场景**：你打开一眼看"此刻哪张单在谁手上、卡在哪步"；出了问题的单能追到每一轮是谁说的什么。

**改版页面逻辑**：

```
列表页：
├─ 顶部状态 Tab：[进行中] [等输入] [已完成] [失败] [全部]
│   默认落在「进行中+等输入」（active 优先，不再新旧混排）
├─ 每行：状态徽章 | 主题 | 参与双方 | 最新动态一句话 | 更新时间
│   └─ 超时标红：派单 4h 没人接 / 干活超 24h（与哨兵规则一致）
└─ 排序：活跃在前，按更新时间倒序

详情页（点行进右栏）：
├─ 状态时间线（submitted→working→completed 每步：谁/何时/正文）
├─ 任务卡全文（可折叠）
├─ RESULT 渲染成键值表（不再裸 JSON）
└─ [等输入状态时] 出现「回复输入」框——人在 UI 里直接补料，task 继续走
```

**业主已定（8-12）**：
- T1 ✅ **UI 可催办/关闭工单**（保留人工口子；催办=发提醒进线程，关闭=业主/admin 权限）
- T2 ✅ 完成单留近 30 天；**列表显示控制：时间周期（24h / 7d / 14d / 30d）× 条目数（20/50/100）+ 翻页**

## 板块 2：Notifications 通知中心

**它是什么**：所有推送的记录台——哪条通知、几点、发到哪个频道、第几档、内容是什么。

**现状（已上线）**：数据来自 ntfy 缓存，**只有近 12 小时**；四列表格（时间/频道/档位/内容）。

**用户场景**："刚才手机响的那条是什么？""运维员今天报过几次警？"——推送打完就散的话，永远查不到。

**改版页面逻辑**：

```
├─ 顶部筛选：频道（user-alerts 响铃 / user-low 静音 / agent:某某）+ 档位 + 日期
├─ 每行：时间 | 频道徽章 | 档位徽章 | 标题 | 内容
│   └─ 3 档内容（含 OTP/正文）默认遮蔽显示 •••，点击才展开（防肩窥）
├─ 频道语义图标：响铃🔔（urgent）/ 静音（low）/ agent 私有频道
└─ 保留「为什么我没收到」的自查入口：该频道最近一条成功推送的时间
```

**业主已定（8-12）**：
- N1 ✅ **落库长期日志，留 30 天**（通知历史是审计性质；ntfy 缓存只是传输层，另建本地通知日志表）
- N2 ✅ **每日推送摘要做**：放两处——Overview 首页放数字卡（今日推送 X 条 / 响铃 Y 次，概览位），Notifications 中心顶部放今日小结条（明细位）

## 板块 3：Push 推送分档 + 设备管理

**它是什么**：两个东西——①每个邮箱身份的"推送内容档位"（1 档只告知有信 / 2 档+主题发件人 / 3 档+正文 OTP）；②哪些手机/设备订阅了推送。

**现状**：档位管理 **UI 已有**（身份行的档位单元格；开 3 档弹风险提示需显式确认）；**设备管理没有 UI**——配对/吊销只能走 API（v0.3.1 的手机配对是一次性凭据流程）。

**用户场景**："hi@ 这个邮箱的信要不要推正文？""我换了手机/丢了一台设备，怎么把它踢下线？"

**改版页面逻辑**：

```
Push 设置页：
├─ 按身份逐行列出：地址 | 当前档位 | [切换档位]
│   档位卡片三选一，每张写人话说明：
│   ├─ 1 档·只告知："有信来了"（不含任何内容）
│   ├─ 2 档·摘要：+ 发件人和主题
│   └─ 3 档·全文：+ 正文和验证码（⚠ 开启弹风险提示，须确认）
└─ 设备管理（新增）：
    ├─ 已配对设备表：设备名 | 订阅了哪些频道 | 配对时间 | [吊销]
    ├─ 吊销立即生效（该设备推送通道作废）
    └─ 「添加设备」按钮 → 生成一次性配对凭据（配合手机 App 扫码/输入）
```

**业主已定（8-12）**：
- P1 ✅ **设备管理面板进 #26**（已配对设备列表+吊销+添加设备引导）
- P2 ✅ 权限原则确认：**自托管=实例 admin（用户自己）全管；托管版=实例主管自己的实例，运营方不碰用户实例内的档位设置**

## 与 AgentMail 对位的差异说明

它的"收件箱级设置"（API Keys / Allow-Block）≈ 我们的"身份级设置"（档位/设备）。它没 task、没推送——这两个板块是我们产品叙事"agent 邮箱 + 任务 + 手机触达"的 UI 载体，#26 里必须一等公民。
